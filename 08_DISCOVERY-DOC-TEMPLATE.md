# **Step 1: Draft the Discovery Document Outline Template**

**This is a structured template your team can actually use inside Confluence, ServiceNow attachments, or document repositories.**

---

# **Discovery Document Template**

*(Used during optional Discovery Process before Concept Note creation)*

---

## **1. Document Metadata**

| Field                         | Description                                                             |
| ----------------------------- | ----------------------------------------------------------------------- |
| **Discovery Document ID**     | Unique identifier (linked to TAP Number)                                |
| **Associated TAP Request ID** | ServiceNow TAP request reference                                        |
| **Requestor/Business Unit**   | Name of the team submitting the cloud service request                   |
| **Date Initiated**            | Start date of discovery activities                                      |
| **Discovery Owner**           | Assigned lead for Discovery coordination (Product Architect or CoP SME) |

---

## **2. Objective and Scope**

| Field                       | Description                                                                                                                               |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Discovery Objective**     | Brief description of what the discovery aims to determine (technical feasibility, security viability, business fit, cost estimates, etc.) |
| **Scope of Discovery**      | Boundaries of what will be investigated (e.g., one cloud provider, specific technologies, PoC vs. PoV, integration scenarios)             |
| **Assumptions/Constraints** | Any known assumptions, dependencies, or constraints limiting discovery work                                                               |

---

## **3. Activities and Methods**

| Field                 | Description                                                                                              |
| --------------------- | -------------------------------------------------------------------------------------------------------- |
| **Methods Used**      | Experiments, lab work, vendor demos, proof-of-concept builds, technical whiteboarding, research analysis |
| **Resources Engaged** | SMEs, external vendors, platform engineers, security architects                                          |
| **Timeline**          | Estimated duration of Discovery activities                                                               |

---

## **4. Findings**

| Field                            | Description                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------------- |
| **Technical Findings**           | Architecture viability, integration feasibility, scalability, reliability considerations |
| **Security Findings**            | Data protection, compliance alignment, risks identified                                  |
| **Cost and Operations Findings** | Expected cost models, operational support impacts, observability considerations          |
| **Summary of Key Risks**         | Identified risks, mitigation strategies (if known)                                       |

---

## **5. Recommendations**

| Field                       | Description                                                                                                      |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **Go/No-Go Recommendation** | Based on findings, should this proceed to Concept Note development?                                              |
| **Suggested Next Steps**    | Actions needed to move forward (e.g., additional PoC, architecture adjustments, formalization into Concept Note) |
| **Open Issues**             | Any unresolved items requiring escalation or future research                                                     |

---

## **6. Approvals and Sign-Offs (Optional if Formalized)**

| Field                            | Description                                                             |
| -------------------------------- | ----------------------------------------------------------------------- |
| **Discovery Lead Approval**      | Signature/approval from Discovery lead/CoP owner                        |
| **Governance Reviewer Approval** | Optional secondary approval if Discovery is especially complex or risky |

---

# **Quick Summary:**

* **Focuses on findings, not solutions yet.**
* **Feeds into Concept Note creation or early project kill/redirection decisions.**
* **Optional approvals depending on scale/impact of discovery outcomes.**
